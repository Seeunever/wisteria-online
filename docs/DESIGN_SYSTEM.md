# 暗格视觉规范 v0.1

状态：阶段 1 设计基线，尚未落地到页面代码。

这套规范服务于“豪门惊情 / 紫藤深宅”的氛围，但产品首先是多人游戏工具。视觉必须帮助玩家快速判断“现在做什么、什么只属于我、什么已经公开”，不能用装饰遮住状态和操作。

## 1. 设计原则

1. **豪门，但不浮夸。** 深色空间承载氛围，旧金只用于重要动作和少量结构线，避免满屏金边。
2. **植物引导视线。** 紫藤枝叶只出现在页边、标题连接处和大面积留白中，不穿过正文、按钮或线索卡。
3. **私密与公开一眼可分。** 私藏使用封闭、深紫、信封感的容器；公开线索使用明亮象牙纸和陈列板语义。
4. **当前行动优先。** 阶段、倒计时或主持人指令、当前可执行动作永远高于装饰、历史记录和玩家列表。
5. **响应式按任务重组。** 电脑、Pad、手机不是同比缩放，而是重新安排“状态、行动、公开信息”的优先级。
6. **剧情内容永不参与公共美术。** 公开插画和纹理只表达宅邸、植物、丝绒、旧纸与金属等通用氛围。

## 2. 色彩角色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 夜幕背景 | `#120D1B` | 页面底色、沉浸区背景 |
| 抬升背景 | `#1D1429` | 导航、侧栏、弹层 |
| 深梅紫 | `#351A47` | 私密容器、选中区块 |
| 行动紫 | `#7955A3` | 主按钮、当前阶段、高亮 |
| 紫藤浅紫 | `#B9A2D3` | 次要强调、植物线条、标签 |
| 旧金 | `#C9AA6B` | 主标题细节、关键编号、结构线 |
| 象牙纸 | `#F1E7D8` | 公开线索卡、阅读型内容 |
| 夜间主文字 | `#F5EFF8` | 深色背景上的正文与标题 |
| 夜间次文字 | `#BBAFC3` | 辅助信息、时间与说明 |
| 墨色文字 | `#251D29` | 象牙纸上的正文 |
| 苔绿 | `#879A79` | 成功、已完成、可继续 |
| 柔酒红 | `#D79AB0` | 错误、风险、不可逆提醒 |

使用规则：

- 行动紫只给当前主要动作；同一区域最多一个实心主按钮。
- 旧金不用于长段正文，也不承担唯一状态编码。
- 私藏与公开除了颜色，还必须同时使用图标、标题和容器形态区分。
- 实现阶段逐项校验 WCAG AA；正文目标至少 `4.5:1`，大字与非文本控件至少 `3:1`。

## 3. 字体与排版

不加载远程字体，避免网络依赖、隐私泄漏和首屏闪烁。

| 类型 | 字体栈 | 建议 |
| --- | --- | --- |
| 品牌与章节标题 | `"Songti SC", "STSong", "Noto Serif CJK SC", serif` | 只用于短标题，营造旧宅与书信气质 |
| 界面与正文 | `system-ui, "Microsoft YaHei UI", "PingFang SC", sans-serif` | 操作、说明、表单与长文本 |
| 房间码与线索编号 | `ui-monospace, "Cascadia Code", Consolas, monospace` | 固定宽度，避免抄录误读 |

字号基线：

- 品牌标题：桌面 `48–64px`，Pad `40–48px`，手机 `36–42px`。
- 页面标题：桌面 `30–36px`，手机 `26–30px`。
- 卡片标题：`18–22px`。
- 正文：桌面与 Pad `16px`，手机不低于 `16px`。
- 辅助文字：不低于 `13px`，关键信息不使用辅助字号。
- 正文行高 `1.6`；长篇角色内容行宽控制在 `36–44` 个汉字附近。

## 4. 间距、边框与层级

- 间距序列：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px`。
- 内容圆角：普通卡片 `12px`，重点面板 `16px`，标签和状态胶囊 `999px`。
- 边框：默认 `1px` 半透明浅紫；重要结构可使用 `1px` 旧金，不叠加厚阴影。
- 阴影：只区分浮层和背景，不模拟高亮霓虹。
- 动效：常规 `160–220ms`；线索翻面或抽屉不超过 `320ms`，并尊重 `prefers-reduced-motion`。

页面最大内容宽度为 `1280px`。背景装饰可以越过内容边界，但交互控件和文字必须留在安全区内。

## 5. 核心组件语言

### 顶部导航

- 左侧为“暗格”字标和当前区域。
- 登录后右侧显示玩家名、房间码或退出入口。
- 手机仅保留字标、房间码和菜单，不复制桌面全部链接。

### 当前阶段卡

- 同时显示阶段序号、阶段名、状态和唯一主要动作。
- 等待房主、正在选择、可调查、已完成等状态不得只靠颜色表达。
- 关键指令保持在首屏；历史说明折叠到次级区域。

### 私藏线索卡

- 深梅紫封闭容器，使用“仅你可见”文字与锁形符号。
- 正面和背面都固定显示相同的稳定编号，例如 `C-03`。
- 翻面只是阅读方式，不改变身份；编号不得因排序、筛选或重载改变。
- “公开”是独立、明确的动作，需要确认反馈；不能把查看背面误作公开。

### 公开线索卡与大看板

- 象牙纸底、墨色正文、旧金编号，视觉上像被钉入陈列板的档案。
- 默认先显示编号、标题、公开阶段和公开者；正文可直接浏览或展开。
- 支持按阶段、编号、公开者筛选，排序规则始终可见。
- 空状态说明“尚无线索公开”，不显示真假剧情占位内容。

### 房间码

- 使用等宽字体、分组间距和复制按钮。
- 视觉展示可以大写，但提交与匹配规则由现有后端保持，不在样式层更改。

### 表单与按钮

- 控件最小触控高度 `44px`，手机主要控件建议 `48px`。
- 输入框字体不低于 `16px`，避免移动端自动缩放。
- 每个视图只保留一个主要实心动作；次要动作使用描边或文字按钮。
- 加载、成功、错误、禁用和焦点状态均需独立设计，不以 toast 代替字段错误。

## 6. 响应式规则

| 范围 | 结构 | 主要行为 |
| --- | --- | --- |
| 手机 `320–639px` | 单栏 | 游戏页使用底部导航；公开看板进入独立面板；首屏只呈现当前行动 |
| Pad `640–1023px` | 一至两栏 | 状态置顶，行动区与个人区并列；公开看板从右侧抽屉或页签进入 |
| 电脑 `1024px+` | 两至三栏 | 游戏页可同时展示阶段、当前行动和公开看板；最大宽度 `1280px` |

布局在 `640px` 和 `1024px` 附近切换；实现时以内容是否拥挤为准微调，不按具体设备型号写死。

### 游戏页空间分配

- 电脑：约 `224–248px / minmax(0, 1fr) / 304–336px`。
- Pad：顶部状态带 + `minmax(0, 1.25fr) / minmax(260px, .75fr)`；公开看板为抽屉。
- 手机：单栏正文 + 安全区感知的底部导航；任何关键按钮不能被导航遮住。

## 7. 可访问性与安全边界

- 所有交互可用键盘完成，焦点环清晰且不被裁切。
- 图标必须配文字或可访问名称；装饰枝叶从辅助技术中隐藏。
- 抽屉打开后管理焦点，关闭后返回触发按钮。
- 线索翻面提供普通按钮和明确状态，不依赖拖拽、悬停或 3D 动效。
- 角色、私藏线索和阶段受限内容继续由服务端授权；CSS 隐藏不构成权限控制。
- 受保护内容不得进入公共图片、静态 HTML、元数据、日志、错误页或截图样例。
