## 2026-08-28 — 修复用户名提交停在进行中

- 起始提交：`25f927f34c8920fc4cb80b3c93a58d01662d5735`
- 结束提交：本条记录所在提交。
- 证据：生产端连续收到用户名入口 POST 并返回 303，但浏览器没有继续请求重定向目标，数据库也没有新增身份；本地浏览器复现确认，`Referrer-Policy: no-referrer` 令表单 POST 携带 `Origin: null` 与 `Sec-Fetch-Site: same-origin`，旧校验拒绝后又错误跳转到内部监听地址，最终被 CSP 阻止。
- 根因：同源校验不接受原生表单将 `Origin` 省略或序列化为 `null` 的情况，也没有按可信代理提供的协议和 Host 还原外部 origin；同时，前端在提交事件内立即禁用 submitter，使失败后页面永久显示“正在进入”。
- 修改：有效的显式 `Origin` 继续严格比对；省略或为 `null` 时只接受浏览器提供的 `Sec-Fetch-Site: same-origin`，并用 Host 与代理协议生成外部跳转地址。无效输入仍显示行内错误，有效提交不再提前锁死按钮。
- 保持不变：身份、会话、房间和私密内容授权逻辑未修改。
- 验证：`pnpm run test:runtime`（13/13）、`pnpm run lint`、`pnpm run build` 与 `git diff --check` 通过；真实浏览器表单已从入口跳转到预置占用身份的错误页并恢复按钮；同源 `Origin: null` 成功路径返回 `/rooms`，同时设置会话与设备凭据。
- 唯一下一步：发布后复验线上入口与静态资源。
