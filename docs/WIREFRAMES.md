# 暗格响应式信息架构与线框 v0.1

状态：阶段 1 设计稿，未修改页面业务逻辑，也未使用真实剧本内容。

本文件定义首页、房间大厅和游戏房间在电脑、Pad、手机上的内容顺序与交互边界。视觉细节见 `docs/DESIGN_SYSTEM.md`。

## 1. 全站信息架构

```text
未登录
└─ 首页
   ├─ 品牌与玩法价值
   ├─ 登录 / 注册
   ├─ 搜证、私藏、公开看板说明
   └─ 通用公开看板预览

已登录
├─ 房间大厅
│  ├─ 创建房间
│  ├─ 输入房间码加入
│  └─ 我的房间
└─ 游戏房间
   ├─ 房间与阶段状态
   ├─ 剧本选择（仅允许的房主状态）
   ├─ 角色选择 / 我的角色
   ├─ 当前行动与搜证
   ├─ 我的私藏线索
   ├─ 已公开线索大看板
   └─ 玩家与房主管理
```

页面层级保持现有路由：`/`、`/rooms`、`/rooms/[code]`。阶段 1 只重组表现，不改接口、数据模型或授权规则。

## 2. 首页

首页只回答三件事：这是什么、为什么好玩、怎样开始。登录注册必须明显，但不压过产品价值。

### 电脑

```text
┌──────────────────────────────────────────────────────────────┐
│ 暗格                      玩法说明          登录状态 / 入口   │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  [紫藤边缘装饰]   豪门深宅中的在线剧本游戏    ┌────────────┐ │
│                   搜证可以私藏，公开才上看板  │ 登录 / 注册 │ │
│                   [开始游戏] [了解玩法]       │ 表单与反馈   │ │
│                                                └────────────┘ │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│  搜索地点         私藏线索            公开到全房间            │
├──────────────────────────────────────────────────────────────┤
│  公开看板预览：编号 / 公开阶段 / 状态（不放剧情占位文案）     │
└──────────────────────────────────────────────────────────────┘
```

- 主按钮进入房间大厅；未登录时滚动或聚焦到账户面板。
- 登录与注册使用同一面板内的页签，不同时展示两套长表单。
- 看板预览负责解释信息形态，不伪造真实线索正文。

- 装饰退到页边，不占首屏高度。

- 不使用横向轮播承载关键说明。

## 3. 房间大厅

大厅的唯一目标是让玩家快速“继续已有房间、加入房间或创建房间”。已有房间优先于新建操作。

### 电脑

```text
┌──────────────────────────────────────────────────────────────┐
│ 暗格 / 房间大厅                              玩家菜单         │
├────────────────────────────────────┬─────────────────────────┤
│ 我的房间                           │ 加入房间                │
│ ┌──────────────────────────────┐   │ [六位房间码] [加入]     │
│ │ 房间名  阶段  人数  [继续]   │   ├─────────────────────────┤
│ └──────────────────────────────┘   │ 创建房间                │
│ ┌──────────────────────────────┐   │ [房间名称]               │
│ │ 房间名  等待中      [进入]   │   │ [创建并进入]             │
│ └──────────────────────────────┘   │                         │
└────────────────────────────────────┴─────────────────────────┘
```

- 有进行中房间时，“继续”是页面主要动作。
- 加入和创建分为两个清晰区块，避免误把房间名当房间码。
- 房间卡只显示玩家已获授权的状态摘要。

### Pad

```text
┌──────────────────────────────────────────────┐
│ 暗格 / 房间大厅                  玩家菜单    │
├──────────────────────────────────────────────┤
│ 我的房间：横向两列或纵向卡片                 │
├──────────────────────┬───────────────────────┤
│ 输入房间码并加入     │ 创建新房间            │
└──────────────────────┴───────────────────────┘
```

### 手机

```text
┌──────────────────────────┐
│ 暗格 / 房间大厅      菜单 │
├──────────────────────────┤
│ 继续上次房间             │
│ [房间摘要         继续]  │
├──────────────────────────┤
│ 加入房间                 │
│ [六位房间码]             │
│ [加入房间]               │
├──────────────────────────┤
│ 创建房间                 │
│ [房间名称]               │
│ [创建并进入]             │
└──────────────────────────┘
```

- 表单单列、按钮全宽，输入房间码时使用适当键盘和自动大写提示。
- 多个旧房间默认收起到“查看全部”，减少首屏噪音。

## 4. 游戏房间

游戏房间按三种信息域组织：全局状态、当前玩家行动、全体公开事实。角色秘密和私藏线索属于当前玩家行动域，绝不因为布局方便进入公共栏。

### 电脑：三栏常驻

```text
┌────────────────────────────────────────────────────────────────────┐
│ 暗格  房间名  [WG-1027 复制]       第 2 阶段      玩家菜单          │
├───────────────┬──────────────────────────────┬─────────────────────┤
│ 阶段与房间状态│ 当前任务                     │ 已公开线索大看板     │
│               │ ┌──────────────────────────┐ │ [阶段][编号][公开者]│
│ 1 角色选择 ✓  │ │ 搜索地点 / 选择动作       │ │ ┌─────┐ ┌─────┐   │
│ 2 调查进行中  │ │ [地点 01] [地点 02]      │ │ │C-03 │ │C-08 │   │
│ 3 尚未开放    │ │ [确认搜索]               │ │ └─────┘ └─────┘   │
│               │ └──────────────────────────┘ │ [浏览全部]          │
│ 房主控制      │                              │                     │
│ 玩家列表      │ 我的角色 / 私藏线索         │ 空状态也保持可见     │
│               │ [仅你可见 C-11] [公开…]     │                     │
└───────────────┴──────────────────────────────┴─────────────────────┘
```

- 左栏和右栏可在长页面中保持可见，中心栏正常滚动。
- 当前任务永远在中心栏首位；角色长文放入可阅读的次级区域。
- 公开看板可以直接浏览，不要求打开另一个页面才能确认全局信息。

### Pad：两栏 + 看板抽屉

```text
┌────────────────────────────────────────────────────┐
│ 房间名  WG-1027    第 2 阶段    [公开看板 8]      │
├────────────────────────────────────────────────────┤
│ 阶段进度：角色选择 ✓ ─ 调查中 ─ 尚未开放          │
├────────────────────────────┬───────────────────────┤
│ 当前任务                   │ 我的角色 / 私藏       │
│ 搜索地点与确认动作         │ 仅本人可见的内容      │
│                            │ [C-11] [公开…]        │
├────────────────────────────┴───────────────────────┤
│ 玩家状态与房主管理（需要时展开）                   │
└────────────────────────────────────────────────────┘
                                   ┌─────────────────┐
                点击公开看板后 →  │ 筛选 + 线索网格 │
                                   │ 右侧抽屉        │
                                   └─────────────────┘
```

- 看板抽屉不会覆盖触发按钮的返回路径，关闭后恢复焦点。
- 横屏仍采用 Pad 结构，只有空间真正足够时才升级为三栏。

### 手机：当前任务优先 + 底部导航

```text
┌──────────────────────────┐
│ 房间名  WG-1027     菜单 │
├──────────────────────────┤
│ 第 2 阶段 · 调查进行中   │
│ 当前指令摘要             │
├──────────────────────────┤
│ 当前任务                 │
│ 选择地点                 │
│ [地点 01]                │
│ [地点 02]                │
│ [确认搜索]               │
├──────────────────────────┤
│ 必要反馈 / 最新结果      │
├──────────────────────────┤
│ 阶段   角色   私藏   看板 │ ← 固定底部导航
└──────────────────────────┘
```

- 默认打开“阶段”，只显示当前行动和必要反馈。
- “角色”“私藏”“看板”是同一房间内的视图切换，不改变服务端权限。
- 底部导航显示公开看板数量和私藏未读状态，但不泄露隐藏内容。
- 房主操作放入受保护菜单；推进阶段必须有明确确认和结果反馈。

## 5. 关键交互状态

### 搜索线索

```text
选择地点 → 显示消耗与可用次数 → 确认 → 等待服务器结果
       → 获得线索：进入“我的私藏”，默认不公开
       → 未获得：说明结果，不伪造线索占位
```

重复点击必须被禁用或幂等处理；加载状态不得提前透露结果。

### 私藏与公开

```text
私藏卡 C-03（仅你可见）
├─ 查看正面
├─ 查看背面（仍为 C-03）
└─ 公开… → 二次确认 → 服务端提交成功 → 从私藏状态转为公开状态
```

- 二次确认明确说明“公开后全房间可见”。
- 公开失败时卡片留在私藏区，并显示可重试反馈。
- 成功后不复制出两个身份不同的卡片；所有视图继续引用同一稳定编号。

### 公开看板

- 默认按“公开时间倒序”，并清楚显示当前排序。
- 支持阶段、编号和公开者筛选；手机筛选使用底部面板。
- 卡片可直接浏览核心内容，详情层保留上下条导航和关闭返回位置。
- 新公开线索以非阻断方式提示，不强制打断正在进行的私密阅读。

## 6. 实现边界与验收点

阶段 2 以后落地页面时，每一页至少检查：

1. `320px` 手机、常见竖屏 Pad、`1024px+` 电脑三种结构。
2. 键盘顺序、可见焦点、抽屉焦点返回和屏幕阅读器名称。
3. 登录失败、空房间、等待房主、无私藏、无公开线索、加载与网络失败状态。
4. 角色内容与私藏线索没有出现在页面源代码、静态产物、日志或未授权请求中。
5. 线索正反面展示同一稳定 ID，并用测试覆盖排序、筛选和刷新后的绑定。
6. 不使用真实剧情内容制作占位图、测试截图或公开文档。

交互式阶段 1 预览是视觉沟通材料，不是可复用生产组件；正式实现应沿用现有 React、服务端授权和项目样式结构。
